==========================================================================
 SWARMBOTS — COMANDOS PARA LA DEMO   (ROS 2 Jazzy + Gazebo Harmonic)
==========================================================================

En CADA terminal, primero cargar el entorno:

  source /opt/ros/jazzy/setup.bash && source ~/swarmbots/swarm_ws/install/setup.bash

Compilar una sola vez (o tras cambiar código):

  cd ~/swarmbots/swarm_ws
  colcon build --symlink-install
  source install/setup.bash

Nota GPU (portátil Optimus): el launch ya fuerza la NVIDIA. Si la ventana 3D
de Gazebo va a tirones, lánzalo headless (headless:=true) y visualiza en RViz.


--------------------------------------------------------------------------
 DEMO 1 — Enjambre dirigido por RViz (control con el ratón)
--------------------------------------------------------------------------
Un enjambre de N Summit (anillo) + N drones; el destino se fija en vivo
clicando en el mapa con la herramienta "2D Goal Pose".

  # Terminal 1 — simulación (Gazebo + warehouse + robots)
  ros2 launch swarm_worlds sim_summit.launch.py n_robots:=3
      # si la GUI va lenta:  ... n_robots:=3 headless:=true

  # Terminal 2 — comportamiento (summits rodean el goal, drones lo sobrevuelan)
  ros2 launch swarm_behavior swarm_behavior.launch.py n_robots:=3
      # variante líder-seguidor:  ... n_robots:=3 mode:=follow

  # Terminal 3 — RViz (visualización + control del destino)
  ros2 launch swarm_behavior rviz.launch.py n_robots:=3

  >> EN RVIZ: pulsar el botón "2D Goal Pose" (barra superior) y hacer clic en
     el mapa. Los Summits van por el suelo (esquivan obstáculos con el LiDAR) y
     se reparten en un ANILLO alrededor del punto (no se amontonan ni "bailan");
     los drones vuelan al mismo punto en capas de altura. Cada clic = nuevo destino.


--------------------------------------------------------------------------
 DEMO 2 — Varios grupos a metas aleatorias con cesión de paso
--------------------------------------------------------------------------
N_GROUPS grupos; cada grupo tiene PAIRS_PER_GROUP pares {Summit + dron} y va a
SU PROPIA meta aleatoria. Dentro del grupo: summits en anillo + drones en capas.
Entre grupos: si las trayectorias se cruzan, el grupo de menor prioridad SE
APARTA para ceder el paso (evita colisiones). Los drones no chocan (van por capas).

  Regla:  nº de robots de la sim  n_robots = n_groups × pairs_per_group

  # Ejemplo: 2 grupos de 1 par (4 robots = 2 summits + 2 drones)
  # Terminal 1
  ros2 launch swarm_worlds sim_summit.launch.py n_robots:=2
  # Terminal 2
  ros2 launch swarm_behavior swarm_pairs.launch.py n_groups:=2 pairs_per_group:=1
  # Terminal 3 (opcional, ver todo en RViz)
  ros2 launch swarm_behavior rviz.launch.py n_robots:=2

  # Ejemplo del demo: 3 grupos de 4 pares (24 robots = 12 summits + 12 drones)
  # Terminal 1   (pesado: si va lento, añade headless:=true)
  ros2 launch swarm_worlds sim_summit.launch.py n_robots:=12
  # Terminal 2
  ros2 launch swarm_behavior swarm_pairs.launch.py n_groups:=3 pairs_per_group:=4
  # Terminal 3
  ros2 launch swarm_behavior rviz.launch.py n_robots:=12

  Opciones útiles de swarm_pairs:
    seed:=5            metas reproducibles (mismas cada vez); -1 = aleatorias
    min_goal_sep:=6    separación mínima entre metas de grupos (m)
    formation_spacing:=2.0   separación entre summits del mismo grupo (anillo)
    cruise_z:=3.5  drone_layer:=1.0   altitud del 1er dron y separación de capas


--------------------------------------------------------------------------
 DEMO 3 — Pinza (gripper) + cámara frontal en el Summit
--------------------------------------------------------------------------
Un Summit con pinza paralela al frente (abre/cierra) + cámara encima de la
pinza. Probar con 1 robot (el control de la pinza va por gz_ros2_control).

  Requisito (una vez):
  sudo apt install -y ros-jazzy-gz-ros2-control ros-jazzy-ros2-control \
                      ros-jazzy-ros2-controllers ros-jazzy-rqt-image-view

  # Terminal 1 — simulación con pinza + cámara (1 robot)
  ros2 launch swarm_worlds sim_summit.launch.py n_robots:=1 gripper:=true

  # Terminal 2 — comprobar que el controlador de la pinza cargó
  ros2 control list_controllers -c /summit0/controller_manager
      # debe aparecer:  gripper_controller ... active

  # Terminal 2 — ABRIR la pinza (dedos a 0.04 m)
  ros2 topic pub --once /summit0/gripper_controller/joint_trajectory \
    trajectory_msgs/msg/JointTrajectory \
    '{joint_names: [finger_left_joint, finger_right_joint], points: [{positions: [0.04, 0.04], time_from_start: {sec: 1}}]}'

  # Terminal 2 — CERRAR la pinza (dedos a 0.0 m)
  ros2 topic pub --once /summit0/gripper_controller/joint_trajectory \
    trajectory_msgs/msg/JointTrajectory \
    '{joint_names: [finger_left_joint, finger_right_joint], points: [{positions: [0.0, 0.0], time_from_start: {sec: 1}}]}'

  AGARRAR BASURA (DetachableJoint, fiable): frente al spawn (sobre (0,18)) hay
  6 objetos (cilindros + cajas). El agarre lo gestiona el nodo grasp_manager:
  cierra la pinza y "pega" el objeto más cercano; al soltar lo despega.

  # Terminal 4 — gestor de agarre (déjalo corriendo)
  ros2 run swarm_behavior grasp_manager --ros-args -p robot:=summit0 -p world:=world_demo

  # Acerca el robot a un objeto (con /summit0/cmd_vel) y luego:
  ros2 topic pub --once /summit0/gripper/grasp   std_msgs/msg/Empty '{}'   # agarrar el más cercano
  ros2 topic pub --once /summit0/gripper/release std_msgs/msg/Empty '{}'   # soltar
      # grasp_manager avisa si no hay objeto dentro de alcance (param grasp_radius, def 0.30 m)
      # mundo empty_arena -> usar  -p world:=empty_arena  (pero la basura está en el warehouse)

  # Terminal 3 — ver la CÁMARA frontal
  rqt_image_view /summit0/camera
      # alternativa:  ros2 run image_tools showimage --ros-args -r image:=/summit0/camera
      # comprobar tasa (~15 Hz):  ros2 topic hz /summit0/camera

  Solo geometría (mover los dedos con sliders, sin Gazebo, en RViz):
  ros2 launch summit_xl_description display_gripper.launch.py
      # requiere: sudo apt install -y ros-jazzy-joint-state-publisher-gui


--------------------------------------------------------------------------
 Sensores extra del Summit (IMU + odometría de encoders)
--------------------------------------------------------------------------
Disponibles en cualquier lanzamiento de la sim (con o sin pinza):

  ros2 topic echo /summit0/imu --once           # IMU (orientación + giro + acel.)
  ros2 topic hz   /summit0/imu                   # ~100 Hz
  ros2 topic echo /summit0/encoder_odom --once   # odom de encoders (deriva)
  ros2 topic echo /summit0/odom --once           # odom ground-truth (motor físico)


--------------------------------------------------------------------------
 Cámara cenital (vista superior de todo el enjambre)
--------------------------------------------------------------------------
Cámara fija mirando hacia abajo sobre la zona de spawn. Disponible en
CUALQUIER lanzamiento de la sim (ya bridgeada por sim_summit).

  rqt_image_view /overhead/image
      # o:  ros2 run image_tools showimage --ros-args -r image:=/overhead/image
      # tasa (~15 Hz):  ros2 topic hz /overhead/image

  Nota: en el warehouse cubre el almacén ENTERO (centrada en (0,0) a 38 m,
  FOV 1.3). Para acercar a una zona concreta, baja el z o reduce el FOV y
  recentra el <pose> del modelo "overhead_camera" en el .sdf del mundo.


--------------------------------------------------------------------------
 DEMO 4 — Teleop con mando PS5 (DualSense) + recoger basura
--------------------------------------------------------------------------
Manejar 1 Summit con gripper usando el mando, para ver el gripper y para
GRABAR demostraciones (entrenar ACT con odom + IMU + cámaras).

  Conecta el DualSense por USB (o Bluetooth) -> aparece /dev/input/js0.
  Comprueba:  ls /dev/input/js*   (y opcional:  ros2 topic echo /joy)

  # Terminal 1 — sim (solo summit + gripper, sin drones)
  ros2 launch swarm_worlds sim_summit.launch.py n_robots:=1 n_drones:=0 gripper:=true

  # Terminal 2 — gestor de agarre
  ros2 run swarm_behavior grasp_manager --ros-args -p robot:=summit0 -p world:=world_demo

  # Terminal 3 — teleop con el mando (SIEMPRE con el launch: arranca joy_node +
  # teleop. 'ros2 run ps5_teleop' solo NO sirve: sin joy_node no hay /joy)
  ros2 launch swarm_behavior teleop_ps5.launch.py robot:=summit0
      # frame del morro (1ª persona, cámara frontal):  ... frame:=body
      # orientado al campo, alinear con tu cámara:      ... view_yaw_deg:=90

  Mando:  stick izq = trasladar · stick der = girar
          R1(btn 10) = agarrar/cerrar · L1(btn 9) = soltar/abrir
  Comprueba que llega:  ros2 topic echo /joy   (si no imprime nada -> driver/mando)
  Si un eje va al revés: arg invert_strafe:=1.0  (o params invert_*/axis_*)

  GRABAR demostración para ACT (observación + acción, en otra terminal):
  ros2 bag record -o demo_$(date +%H%M%S) \
    /summit0/odom /summit0/imu /summit0/camera /overhead/image \
    /summit0/joint_states /summit0/cmd_vel \
    /summit0/gripper/grasp /summit0/gripper/release

  CONVERTIR el bag a HDF5 (formato ACT, un archivo = un episodio):
  pip install --user h5py    # dependencia (una vez)
  python3 ~/swarmbots/swarm_ws/scripts/bag_to_act_hdf5.py demo_XXXXXX -o episode_0.hdf5
      # verificar cámaras a ojo (vuelca PNG en ./debug_frames):
      #   ... demo_XXXXXX -o ep.hdf5 --debug_dump_frames 5
      # lote:  for d in demo_*; do python3 scripts/bag_to_act_hdf5.py "$d" -o "$d.hdf5"; done
      # salida (defaults, robot MECANUM):
      #   /observations/qpos  [yaw, gripper]        (EGOCENTRICO; --include_xy anade x,y)
      #   /observations/qvel  [vx, vy, wz]  + /imu (10)  + images/{front,overhead}
      #   /action  [cmd_vx, cmd_vy, cmd_wz, grasp]  (grasp latcheado 0/1)
      # flags:  --hz 30 (grasp a mas frecuencia)   --include_xy (pose mundial en qpos)
      #         --no-holonomic (robot skid-steer -> action = [vx, wz, grasp])
      #         --robot summit0   --overhead-topic /overhead/image
